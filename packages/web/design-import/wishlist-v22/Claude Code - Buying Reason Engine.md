# Claude Code: рушій рекомендацій «Зараз вигідно купити»

> Технічна специфікація бізнес-логіки секції «Зараз вигідно купити» на
> сторінці «Бажанки». Прототип (`Бажанки v2.2.html` → `wl22-app.jsx` +
> `wl-buying-reasons.js`) вже демонструє повну поведінку. **Ревізія
> 2026-07-08 (той самий день):** звужено до 3 причин, що доводять реальний
> історичний рух ціни за власним трекінгом Knyhovo — див. §1. Це продуктова
> логіка, НЕ редизайн — візуал не змінювався.

---

## 1 · Core positioning — довіра, не маркетинг

Knyhovo допомагає користувачу купити книгу у справді вигідний момент.
Секція НІКОЛИ не спирається на:
- ціну «було», яку показує книгарня,
- відсоток знижки, заявлений книгарнею,
- «найкращу пропозицію серед книгарень» саму по собі (це порівняння цін
  між книгарнями, а не доказ падіння ціни в часі),
- факт «знову в наявності» (це подія наявності, а не цінова подія).

Єдине джерело правди — власний щоденний трекінг ціни Knyhovo (`prevPrice`,
`min90`, `targetPrice` — усі нижче). Користувач має відчувати:

> «Knyhovo допомагає мені купити у правильний момент» —

а не:

> «Ця книгарня стверджує, що є знижка».

## 2 · Що це за фіча

«Зараз вигідно купити» — НЕ ще один список бажанок. Це персональний
рекомендаційний рушій, який відповідає на одне питання:

> «Які книги з моїх бажанок варто купити просто зараз?»

Книга потрапляє в цю секцію ЛИШЕ якщо для неї є конкретна, історично
доведена причина. Книги без причини лишаються у звичайних бажанках («Решта
бажанок»), навіть якщо вони дешеві.

## 3 · BuyingReason — enum (платформо-незалежний, ревізія 2026-07-08)

```ts
enum BuyingReason {
  TARGET_REACHED = 'TARGET_REACHED',  // 1 · досягнуто цільової ціни користувача
  LOWEST_90_DAYS = 'LOWEST_90_DAYS',  // 2 · мінімум за останні 90 днів (власний трекінг)
  PRICE_DROPPED  = 'PRICE_DROPPED',   // 3 · ціна впала з моменту останньої перевірки Knyhovo
}
```

**Видалено з enum (не використовувати в цій секції):** `BEST_OFFER`,
`BIG_DISCOUNT`, `BACK_IN_STOCK`, `GOOD_DEAL`. Вони НЕ доводять реальний
історичний рух ціни за власним трекінгом Knyhovo:
- `BEST_OFFER`/`GOOD_DEAL` порівнювали книгарні між собою — це порівняння,
  не історія;
- `BIG_DISCOUNT` спирався на той самий percent-off патерн, якому
  користувачі не довіряють, коли його показують самі книгарні;
- `BACK_IN_STOCK` — це подія наявності, не цінова подія.

Якщо колись знадобиться повідомити «знову в наявності» — це окреме,
не-цінове сповіщення, а не бейдж цієї секції.

Кожна книга отримує РІВНО ОДНЕ значення `BuyingReason`. **UI ніколи не
вирішує, який бейдж показати** — лише мапить готовий enum на іконку+підпис
(§5). Логіка живе в `wl-buying-reasons.js`
(`window.KnyhovoBuyingReasons.evaluateBook/evaluateCatalog`) — чистий JS
без UI-залежностей, тож його легко замінити на виклик реального API.

## 4 · Правило пріоритету

Перше співпадіння зверху вниз зупиняє оцінку (і фіксує `savingsUAH`, §6):

1. **TARGET_REACHED** — `price <= targetPrice` (користувач задав цільову ціну)
2. **LOWEST_90_DAYS** — `price <= min90` (мінімум за 90 днів власного трекінгу)
3. **PRICE_DROPPED** — `price < prevPrice` (будь-яке зниження від
   попередньої перевірки Knyhovo — немає окремого порогу «великої
   знижки»; розмір знижки впливає лише на сортування всередині групи, §6)

Якщо ЖОДНА умова не істинна → книга НЕЕЛІГІБЕЛЬНА (`null`), лишається
тільки у «Решта бажанок». **Немає фолбек-причини** — на відміну від
попередньої ревізії цього документа, книга без одного з цих трьох сигналів
просто не показується тут (а не отримує узагальнений «вигідна пропозиція»
бейдж).

## 5 · Мапінг бейджів (презентаційний шар — НЕ бізнес-логіка)

| BuyingReason   | Підпис (UA)             | Іконка (Lucide outline) |
|----------------|--------------------------|--------------------------|
| TARGET_REACHED | Досягнуто вашої цілі      | target |
| LOWEST_90_DAYS | Найнижча за 90 днів        | trending-down |
| PRICE_DROPPED  | Подешевшала                  | arrow-down |

Рівно один бейдж на картку, завжди зелений тон (позитивна подія). **Немає
карток без бейджа. Немає карток із двома бейджами.**

## 6 · Сортування

НЕ за ціною, НЕ за відсотком знижки:

```
sort by: [priorityRank(reason) ASC, savingsUAH DESC, title ASC (тай-брейк)]
```

`savingsUAH` — та сама формула для всіх трьох причин: `prevPrice - price`
(для TARGET_REACHED/LOWEST_90_DAYS без окремого `prevPrice` — рахується
відносно `targetPrice`/`min90` відповідно). Жодних окремих формул
порівняння книгарень — усе походить із власної цінової історії книги.

## 7 · Немає ліміту, немає штучного заповнення

Показуються ВСІ книги, що пройшли перевірку — 3, 9 чи 27; жодного
максимуму. Якщо кваліфікованих книг 0 — замість каруселі показується
порожній стан:

> «Сьогодні вигідних пропозицій ще немає. Книговик стежить за цінами і
> повідомить, щойно з'явиться щось цікаве.»

У прототипі: твік «Показати порожній стан» форсує цей режим для демонстрації.

## 8 · Десктоп vs мобільний — тільки презентація

Бізнес-логіка й відсортований список ІДЕНТИЧНІ для обох:
- **Десктоп** — пейджинована карусель, сторінка = сітка 2×2 (4 книги).
- **Мобільний** — свайп-карусель по одній картці, та сама колекція.

Обидва мапують один і той самий enum на один і той самий бейдж (§5) —
жодних розбіжностей у тому, ЧОМУ книга показана.

## 9 · Дані мок-каталогу (прототип, ревізія 2026-07-08)

`wl22-app.jsx → WL21_SALE_CANDIDATES` — ті самі 12 книг, жодної нової.
Приховані офери книгарень і прапорець «знову в наявності» видалені з
мок-даних разом із правилами, які на них спирались:

- `targetPrice` — 1 книга («Тигролови») → TARGET_REACHED
- `min90` — 1 книга («1984») → LOWEST_90_DAYS
- 7 книг — звичайний PRICE_DROPPED (реальне зниження від `prevPrice`,
  різного розміру — немає окремого порогу «великої знижки»)
- 3 книги («Дофамінове покоління», «Інтернат», «Сто років самотності») —
  ціна не змінювалась і немає ні цілі, ні 90-денного мінімуму → НЕ
  кваліфікуються → автоматично переносяться у «Решта бажанок»
  (`WL21_SALE_OVERFLOW`). Дві з них раніше показувались тут через
  BACK_IN_STOCK/GOOD_DEAL — це навмисна демонстрація нового, суворішого
  правила довіри: без реального руху ціни книга сюди не потрапляє.

Порада Книговика (Hero-блок) НЕ підключена до цього рушія — окрема,
вручну курована рекомендація, за прямою вимогою продукту.

## 10 · Пропонований API-контракт

```
GET /api/wishlist/buying-opportunities

Response 200:
{
  "items": [
    {
      "bookId": "tygrolovy",
      "reason": "TARGET_REACHED",
      "savingsUAH": 25,
      "price": 15000,          // копійки
      "prevPrice": 17500,      // Knyhovo's OWN last tracked price —
                                 // NEVER the store's displayed "old price"
      "currency": "UAH",
      "store": "Rozetka"
    }
    // … відсортовано за priorityRank ASC, savingsUAH DESC — бекенд віддає
    // ГОТОВИЙ порядок, фронтенд НЕ пересортовує і не перевибирає reason
  ],
  "totalWishlistCount": 24
}
```

- `reason` ∈ `{TARGET_REACHED, LOWEST_90_DAYS, PRICE_DROPPED}` — жодного
  іншого значення бекенд не повинен повертати для цього ендпоінта.
- `prevPrice`/`min90` мусять походити виключно з таблиці власної історії
  цін Knyhovo (щоденний трекінг), НІКОЛИ з поля store-side "compare at
  price"/"was price" у фіді книгарні — навіть якщо це поле точне, воно не
  є прийнятним доказом для цієї секції.
- Порожній `items: []` → фронтенд показує порожній стан (§7), НЕ помилку.
- Книги без `reason` НЕ включаються в цю відповідь — вони йдуть звичайним
  списком через наявний `GET /api/wishlist`.

## 11 · Мобільна й десктопна поведінка — підсумок для QA

- Обидві платформи використовують ОДНУ відповідь API/один
  `evaluateCatalog()` виклик — не два окремих запити з різною логікою.
- Зміна ціни на бекенді може: (a) додати книгу в секцію, (b) прибрати
  книгу з секції назад у «Решта бажанок», (c) змінити її бейдж (напр.,
  PRICE_DROPPED → LOWEST_90_DAYS, якщо нова ціна виявилась мінімумом за
  90 днів), (d) змінити її позицію в каруселі. Усе це — очікувана
  поведінка, не баг.
- Немає максимальної кількості карток на жодній платформі.

## Не змінювати

Візуальний рецепт карток (`.wl21-sale`, `.wl22-mob`, кольори, радіуси,
тіні), структуру каруселей (2×2 десктоп / 1-в-кадрі мобільний), Hero/
«Порада Книговика» (лишається незалежною), бейдж-пілюлю
(`.wl21-badge--green`). Не повертати `BEST_OFFER`/`BIG_DISCOUNT`/
`BACK_IN_STOCK`/`GOOD_DEAL` без окремого продуктового рішення — вони були
свідомо видалені через недостатню довіру до джерела доказу.
