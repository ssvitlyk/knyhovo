Author Shelf — «Інші книги автора»

Офіційна, заморожена специфікація полиці «Інші книги автора» для імплементації. Це єдиний новий UI-компонент W9a. Він розширює Book Details v1.1 (Variant C) — не вводить нових сторінок, не змінює Search Results і не торкається hero Book Details. Складено виключно з замороженого BookCard, каркасу полиць Book Details v1.1 та токенів DS v1.0.

✦ Author Shelf v1.0 — затверджено 20.06.2026 · W9a · заморожено для імплементації. Майбутні ітерації можуть розширювати функціональність, але не переробляти ці візуальні основи.

⚠ Живі приклади є нормативними. Якщо проза й приклад суперечать — перемагає приклад.

Живий патерн (Author Shelf — Live Pattern) і рендери в цьому документі — єдине джерело візуальної правди для розкладки, розмірів і поведінки. Обидва відтворюються з того самого author-shelf.jsx + author-shelf.css, що й продакшн.

1 · Призначення та принцип

Полиця відповідає на одне читацьке питання наприкінці сторінки книги: «Що ще писав цей автор?» Це природне продовження читання — від однієї книги до решти доробку автора, без нового пошуку.

  • Відкриття, не функція. Полиця — необов'язкова поверхня відкриття (W9a). Вона ніколи не конкурує з рішенням «де купити»; вона стоїть в самому низу, після всього основного контенту.
  • Реюз, не редизайн. Картка — це заморожений BookCard; сітка й рейл — заморожений каркас полиць Book Details v1.1. Нової візуальної мови немає.
  • Тиша краща за шум. Якщо показувати майже нічого — полиця зникає повністю. Жодних плейсхолдерів, жодного «нічого не знайдено», жодного добивання сітки порожніми клітинками. (Принцип «один тисяча ні на кожне так».)
  • Спокій без гонитви. Жодних «бестселер», лічильників, «🔥». Порядок — у наявності й найдешевше; це не таблиця лідерів.

2 · Реальність даних і деградація

Сьогодні автор у каталозі — це текстове поле canonical_books.author: без сутності, без ID, без дедуплікації. Звідси три обмеження, під які спроєктовано компонент.

Ризик данихПоведінка компонента
Неповні збіги — варіації написання («Т. Шевченко» / «Тарас Шевченко») розривають збіг.Полиця показує лише те, що реально зматчилось, і не обіцяє повноти. «Усі книги автора →» веде на сторінку автора (Search Results), де користувач бачить весь відфільтрований список.
Шумні імена — той самий рядок автора міг би відрізнятися від картки до картки.Рядок автора на картці приховано (він і так дублює заголовок секції) — тож варіації написання не виходять на поверхню. Series-полиця цього не робить; правило стосується лише author-полиці.
Малі набори — у автора часто 0–3 інші книги в каталозі.Поріг min = 2: при 0 або 1 книзі секції немає взагалі. При 2–3 — показуємо рівно стільки, без добивання.

Канонічна сутність автора, дедуплікація написань і будь-яка author-intelligence — це W9b і поза скоупом цієї специфікації (узгоджено з W9 §12).

4 · Розміщення в Book Details

Полиця — остання контентна секція сторінки: одразу після полиці «Книги серії» і перед футером. Порядок заморожений (успадковано з Book Details v1.1 + Price History v1.2.1):

Відношення до метаданих: завжди нижче блоку «Про видання» — метадані стосуються цього видання, полиця розширює погляд назовні, до доробку автора. Відношення до Price History: завжди нижче «Динаміки ціни». Полиця ніколи не піднімається над цими блоками й ніколи не стає окремою сторінкою.

Порядок двох полиць (заморожено): «Книги серії» — перша (вужчий, релевантніший зв'язок), «Інші книги автора» — друга (ширший зв'язок). Якщо серії немає, author-полиця може бути єдиною полицею.

7 · Десктоп-розкладка ≥1024px

  • Ширина секції: полиця-контейнер (.as-shelf) завжди на повну ширину контенту Book Details (двопанельна сітка Variant C тут уже не діє) — незалежно від кількості карток.
  • Колонкова модель (єдиний механізм): кількість колонок = min(карток, rowCap). Кожен брейкпоінт — окремий інстанс селектора, тож його --as-cols уже дорівнює min(cards, rowCap) (десктоп cap 4 → min(cards,4); таблет cap 3 → min(cards,3)); CSS розгортає у repeat(var(--as-cols), minmax(0, var(--as-card-max))). auto-fit/auto-fill заборонені — вони створюють порожні треки або розтягують картки. gap: --space-5; justify-content: start.
  • Коли видимих книг < cap (ключове правило): колонок рівно стільки, скільки карток; 2 книги → 2 картки, 3 → 3, 4 → 4. Жодних порожніх чи зарезервованих треків; решта ряда — порожній простір контейнера (ліворуч), не клітинки сітки. Це узгоджує §7 із §9.
  • Розмір картки (анти-розтягування): обкладинка 104×150 фіксована (frozen); кожен трек — minmax(0, 272px), включно з повним 4-up рядом, тому ширина картки ідентична для 2, 3 чи 4 карток (ніякого «стрибка» ширини залежно від кількості). Мін ≈136px (обкладинка + 2×16 padding; min-width:0 на картці — ніколи вужче), макс 272px (--as-card-max).
  • Щільність: рівно один ряд — максимум 4 картки (cap=4). Більше книг → «усі книги автора (N) →» на сторінку автора. Без другого ряду й без пагінації на сторінці книги.
  • Картка: вертикальний .kn-book (flex-direction: column — page-level override), обкладинка 104×150.
  • Заголовок-рядок (.as-head): h2 «Інші книги автора» зліва, «усі книги автора →» справа, align-items: baseline; justify-content: space-between.

8 · Мобільна розкладка <768px

  • Горизонтальний рейл (.as-shelf--mob): свайп, успадковано з мобільних полиць Book Details v1.1. Картки flex: none; width: 168px, обкладинка 96×138.
  • Edge-bleed (точний намір): margin: 0 calc(-1*--space-4) + такий самий padding — перша картка повністю видима і притиснута до лівого гаттера контенту; картки йдуть управо; правий край viewport обрізає наступну картку до часткового peek — саме цей peek є єдиним сигналом, що рейл скролиться (ніяких стрілок/точок). Повністю порожньої правої картки бути не має.
  • Свайп: scroll-snap-type: x proximity; кожна картка scroll-snap-align: start + scroll-padding-left: --space-4 — спіймана картка сідає рівно в лівий гаттер. Скролбар прихований; -webkit-overflow-scrolling: touch.
  • Поведінка картки: та сама вертикальна .kn-book; рядок автора так само прихований.
  • Трейлінг-картка «усі»: коли книг більше за cap — остання у рейлі a.as-railmore (іконка + «Усі книги автора» + «N книг») веде на сторінку автора. scroll-snap-align: end.
  • Cap на мобільному — 8 карток у рейлі (свайп дешевший за клік); далі — трейлінг-картка.
  • 44px цілі дотику на всіх інтерактивних елементах.

9 · Порожні стани й поріг ядро деградації

На відміну від Price History (який ніколи не схлопується, бо це частина рішення про покупку), Author Shelf — необов'язкове відкриття, тож при нестачі книг його коректно прибрати повністю.

Кількість зматчених книгПоведінка
0 (немає інших книг / автор порожній)Секції немає. selectAuthorShelf → show:false, компонент повертає null. Жодного заголовка, рамки чи плейсхолдера.
1 (нижче порогу)Секції немає. Полиця з однієї книги — це не полиця; вона додає шум. Поріг min = 2.
2–4Сітка/рейл рівно з наявних карток: кількість колонок = кількості карток (data-count). Без добивання порожніми клітинками/зарезервованими треками, без «усі →». Див. §7 і «Інваріанти розкладки» нижче.
> cap (5+ десктоп · 4+ таблет · 9+ мобільний)Показуємо cap карток + «усі книги автора (N) →» (десктоп/таблет) / трейлінг-картку (мобільний) → сторінка автора.

Мінімум N = 2. Це єдиний поріг приховування. Немає окремого «empty state» з ілюстрацією чи маскотом — маскот Книговик на цій полиці не з'являється ніколи (вона не входить у дозволені W8c поверхні empty/first-book/unavailable). Порожнеча = відсутність секції.

Картки завжди розкладаються у звичайну сітку (2 книги → 2 картки, 3 → 3, 4 → 4) — без overlap, stacking, fan чи absolute positioning. Приклади показані на повну ширину контенту Book Details, де живе сітка 4-up.

3 книги → 3 звичайні картки · колонок = карток · без «усі», без добивання
0–1 книга → секцію омітнуто (нічого не рендериться)

Інваріанти розкладки (implementation-safe)

  • Кількість колонок = кількості видимих карток (до cap). Ніколи більше.
  • Жодних порожніх клітинок сітки і жодних зарезервованих треків.
  • Жодних filler-карток / плейсхолдерів, щоб заповнити ряд.
  • Жодного overlap (накладання карток).
  • Жодного fan / stacking (віяло/стос карток).
  • Жодного position: absolute для карток — лише grid (десктоп/таблет) або flex-рейл (мобільний).
  • Картка ніколи не розтягується > 272px і ніколи не звужується < обкладинки+padding (≈136px).
  • Полиця-контейнер завжди на повну ширину контенту — при < cap незайнятий простір лишається порожнім праворуч, картки ліворуч.

10 · Відбір і порядок

Селектор selectAuthorShelf({ currentId, roster, seriesIds, cap }) — єдине джерело правди:

  1. Виключення (єдиний ключ = канонічний id): прибрати поточну книгу (currentId) та всі книги з Series-полиці (seriesIds). Дедуп — за id, ніколи за назвою (назви збігаються між виданнями й ламаються на шумних рядках).
  2. Сортування: у наявності спершу (out-of-stock — в кінець), потім за зростанням ціни, потім tie-break за id (детерміновано між запитами). Спокійний порядок — не рейтинг.
  3. Availability map: 'in' / 'low' (обидва = в наявності для сортування) / 'out' (ціна «—», в кінець). Якщо всі книги out-of-stock — полиця все одно показується (каталог автора існує); приховується лише при total < 2.
  4. Поріг: show = total ≥ 2.
  5. Зріз: books = sorted.slice(0, cap); hasMore = total > cap; cols = min(books.length, cap) (явна кількість колонок).
function selectAuthorShelf({ currentId, roster, seriesIds = [], cap = 4 }) {
  const series = new Set(seriesIds);
  const pool = roster.filter(b => b.id !== currentId && !series.has(b.id)); // dedup by id
  const sorted = [...pool].sort((a, b) => {
    const ao = a.avail === 'out', bo = b.avail === 'out';
    if (ao !== bo) return ao ? 1 : -1;                       // in-stock first
    const pa = a.price ?? 1e9, pb = b.price ?? 1e9;
    if (pa !== pb) return pa - pb;                            // then cheapest
    return String(a.id).localeCompare(String(b.id));         // deterministic tie-break
  });
  const total = sorted.length, books = sorted.slice(0, cap);
  return { show: total >= 2, books, total, hasMore: total > cap, cols: Math.min(books.length, cap) };
}

12 · Взаємодія

  • Ціль кліку — вся картка. BookCard загорнутий у a.as-link (block) → leaf Book Details цієї книги. Обкладинка, назва, ціна — все веде на сторінку книги.
  • Hover картки: успадковано з .kn-book:hover — підйом 2px + --shadow-lg, --dur-base ease-out. Без нових ефектів.
  • «усі книги автора →» / трейлінг-картка → сторінка автора (Search Results, відфільтрований за рядком автора список — frozen, W9a). Hover → --accent-hover / межа й тінь.
  • Анімація появи: одноразовий stagger (.as-stagger, 280ms ease-out, 50ms каскад), гейтований на prefers-reduced-motion: no-preference. Жодних нескінченних циклів. Під reduced-motion — статика.
  • Свайп (мобільний) — нативний, з scroll-snap proximity. Без JS-керованого скролу.

13 · Доступність

  • Семантика: section з data-screen-label; заголовок h2 у природному порядку сторінки (після h2 Series-полиці).
  • Картка-посилання: a.as-link з aria-label="Перейти до книги «{назва}»"; внутрішній BookCard отримує tabIndex={-1}, щоб не було подвійної зупинки табуляції. Один елемент фокусу = одна картка.
  • Порядок табуляції: зліва-направо, зверху-вниз (десктоп-сітка) / порядок рейлу (мобільний). Фокус на позаекранній картці рейлу нативно вводить її у видиму зону (без scrollIntoView).
  • Фокус: 3px м'яке акцентне кільце (--focus-ring) на .as-link, .as-all, .as-railmore через :focus-visible.
  • Цілі дотику: ≥44px на мобільному (вся картка + трейлінг-картка значно більші).
  • Прихований автор прибраний через display:none — його немає і в дереві доступності, тож скрінрідер не читає повторюване ім'я на кожній картці; ім'я автора лишається в hero та заголовку секції.
  • Обкладинка-плейсхолдер — aria-hidden (декоративна), назва книги несе сенс.

15 · Теми (світла / темна)

Тема перемикається через data-theme="light|dark" на <html>. Усе ре-темиться через токени — однакові метрики, інші лише кольори. Жодного хардкоду кольору немає. Картки, ціни-акценти, межі й тіні — ті самі токени, що й у решті Book Details.

17 · Нотатки імплементації

  • Композиція (єдиний контракт): рендерити window.AuthorShelfKit.AuthorShelfSection — вона викликає селектор ТРИЧІ (cap:4 desktop, cap:3 tablet, cap:8 mobile) і рендерить ТРИ wrapper-и (.as-desktop + .as-tablet + .as-mobile); CSS показує рівно один на брейкпоінт (desktop ≥1024 · tablet 768–1023 · mobile <768). Це єдиний підтримуваний адаптивний свіч — не перетворювати одну сітку на рейл через media. Кожен інстанс має власний cap, тож кількість колонок = кількості карток у кожному діапазоні (4-та книга на таблеті йде в «усі →», а не у другий ряд). Увага: неймспейс — window.AuthorShelfKit (НЕ window.AuthorShelf: React-компонент AuthorShelf затінив би однойменний глобал). DS-примітиви — з window.KnyhovoDesignSystem_9fa616.
  • Кількість колонок: кожен інстанс передає одну явну інлайн-змінну --as-cols = min(cards, rowCap) свого брейкпоінта (desktop 4, tablet 3); CSS розгортає її у repeat(var(--as-cols), minmax(0, var(--as-card-max))). auto-fit/auto-fill заборонені (створюють порожні треки / розтягують картки).
  • Прив'язка до backend: roster = SELECT * FROM canonical_books WHERE author = :author AND id != :currentId + best-price join (provider_listings); availability мапиться в 'in'|'low'|'out'. Без нової інфраструктури — read-only за наявним текстовим полем.
  • Дедуплікація з Series-полицею робиться у селекторі за id (передати seriesIds), не в розмітці. Той самий id-ключ виключає і поточну книгу.
  • Без Tailwind. Лише author-shelf.css + токени DS. Усі переозначення — на рівні сторінки (.as-shelf .kn-book__author{display:none} тощо); BookCard недоторканий.
  • Полиця рендериться тільки коли show === true. Не монтувати порожній контейнер «про запас».
  • Обкладинки сьогодні null → теплий паперо-плейсхолдер BookCard; полиця не блокується на обкладинках (узгоджено з W9 відкритим питанням про обкладинки).

18 · Не змінювати

  • Розміщення — завжди остання контентна секція, після Series-полиці, перед футером.
  • Поріг min = 2: при 0–1 книзі секція повністю відсутня (жодного плейсхолдера, жодного маскота).
  • Реюз замороженого BookCard; жодного нового дизайну картки.
  • Приховування рядка автора на author-полиці (Series-полиця — без змін).
  • Показані/приховані поля картки та метадата-ієрархія (ціна-акцент › стара-muted › книгарня-muted).
  • Cap (4 десктоп / 8 мобільний) + «усі книги автора →» на сторінку автора замість другого ряду/пагінації.
  • Порядок відбору (виключення серії + поточної; у наявності → найдешевше).
  • Сітка 4-up (десктоп) / 3-up (таблет) / горизонтальний рейл (мобільний); брейкпоінт 768px. Кількість колонок = кількості видимих карток (без порожніх треків/filler); картка 136–272px; без overlap/fan/absolute.
  • Одноразова поява без нескінченних циклів; reduced-motion статика.
  • Токени, типографіка, радіуси, тіні DS v1.0 та всі захищені бренд-активи (лого, маскот).
  • Search Results і hero Book Details — не торкатися.
