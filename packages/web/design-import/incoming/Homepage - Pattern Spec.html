KNYHOVO DESIGN SYSTEM · HOMEPAGE · PATTERN SPEC

Knyhovo Homepage v1.0

Фінальна архітектура головної сторінки. Фундамент — Концепт A (Oracle Search): пошук як серце продукту, відкриття — полицями нижче. Складена виключно з затверджених компонентів DS v1.0. Жоден захищений актив не змінено; патерни Search Results, Book Details і Бажанки не зачеплено.

✦ Кандидат на заморозку · переглянуто 21.06.2026 · рекомендація щодо freeze — у кінці документа

1 · Фінальна архітектура

Knyhovo — насамперед платформа порівняння цін на книги. Пошук залишається ядром користувацького шляху і домінує на головній. Відкриття (discovery) — це полиці під пошуком, а не рівноправний другий вхід.

Обрана ставка

З п'яти досліджених концептів за основу взято Концепт A · Oracle Search. Відхилено: D (Two Doors) — розщеплена архітектура; C (Price Intelligence) як фундамент; E (Discovery Hub) — журнальна головна; важкі редакційні / блогові макети; кілька конкурентних точок входу.

Шлях користувача

Приземлення → пошук за назвою / автором / ISBN → Результати пошуку → Деталі книги. Без конкретного запиту читач скролить полиці відкриття (Популярне · Новинки · Knyhovo радить) і входить у ту саму воронку через BookCard.

Layout / chrome (page-level, не компоненти DS)

  • .site-header / .site-footer — успадковано без змін від затвердженого website-патерну та Search Results.
  • .hero — затверджений макет 50/50 з ui_kits/website; розмітка та пропорції без змін.
  • .hp-grid — 2-кол. сітка горизонтальних BookCard (та сама механіка, що у frozen Search Results).
  • .hp-recommends--framed — виділений --surface-accent блок; лише фон + рамка з токенів, без нового візуального словника.

Захищені активи

  • Логотип: knyhovo-logo-light/dark.png — без змін, перемикання за темою.
  • Книговик у Hero: mascot-hero-light/dark.png — затверджена ілюстрація, ідентичні масштаб і позиція в обох темах.
  • Аватар Книговика в «Knyhovo радить»: avatar-light/dark.png — затверджене обличчя-аватар.

6 · Заборонено змінювати

  • Hero — затверджений макет 50/50, типографіка, копірайтинг «Де купити цю книгу? / Knyhovo знає.», позиція й масштаб Книговика.
  • Кількість і порядок секцій: Hero → Популярне зараз → Новинки → Knyhovo радить.
  • «Knyhovo радить» залишається books only — без статей, журнального макета чи блогових карток.
  • Frozen BookCard — без нових варіантів карток; ієрархія ціна › стара ціна › книгарня; правило max один бейдж.
  • Палітра, типографіка, радіуси, тіні, спейсинг — лише токени DS v1.0.
  • Патерни Search Results, Book Details, Бажанки — не редизайнити.
  • Захищені бренд-активи (логотип, Книговик, аватар).

7 · Рекомендація щодо заморозки

✦ Готово до freeze — рекомендовано заморозити як Homepage v1.0

Архітектура повністю узгоджена з продуктовою стратегією (search-first), складена виключно з затверджених компонентів DS v1.0, не вводить нового візуального словника й не зачіпає жодного замороженого патерну. Обидві теми та обидва брейкпоінти відпрацьовано. Сторінка готова до заморозки і передачі в розробку.

Перед фінальним freeze — підтвердити з продуктом (не блокери):

  • Джерела даних полиць. Підтвердити логіку «Популярне зараз» (вікно популярності) та «Новинки» (поріг свіжості), а також хто і як курує «Knyhovo радить».
  • Обкладинки книг. Жива версія використовує warm-плейсхолдери BookCard. Перед freeze підключити реальні обкладинки (проп cover) — візуальної зміни патерну не потребує.
  • Призначення CTA. «Усі →», «Весь каталог →», «Уся добірка» мають вести на Search Results з відповідним фільтром.
  • Стан без даних. Якщо полиця порожня (немає активних знижок / новинок) — секція ховається; підтвердити правило з продуктом.
